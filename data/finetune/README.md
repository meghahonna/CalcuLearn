# CalcuLearn finetuning dataset

Generated by `scripts/finetune/exportDataset.ts` from the authored content in
`content/concepts/` and the problem bank in `src/data/problems.ts`.
Regenerate any time with: `npx tsx scripts/finetune/exportDataset.ts`

## Format

mlx-lm chat format, one record per line:
`{"messages": [{"role": "user", "content": "<runtime prompt>"}, {"role": "assistant", "content": "<target>"}]}`

Prompts byte-match the runtime formats in `dialogueGenerator.ts` and
`responseClassifier.ts`, so the finetuned model is a drop-in swap.

## Splits

- `train.jsonl` / `valid.jsonl` — random 92/8 split, deterministic (seed 20260707)
- `test.jsonl` — ALL records from two fully held-out concepts
  (`deriv.quotient-rule`, `integ.by-parts`) to test generalization to unseen concepts

## Task mix (1,321 records)

| Task | Count | Target source |
|---|---|---|
| classifier (single label) | 469 | checks + misconceptions + synthetic off-topic |
| hint (Socratic) | 246 | problem solutionSteps hints |
| feedback | 207 | gold `socratic_response_md` (misconceptions) + composed correct/incorrect |
| semantic-eval (JSON) | 202 | canonical answers, misconception wrong answers, non-answers |
| intro | 99 | composed from concept one-liners + first-step hints |
| worked-example | 60 | concept example steps (≤150 words) |
| problem-variant (JSON) | 38 | same-concept/difficulty problem pairs |

## Training (M5, 32GB — after picking the base model per FINETUNING_PLAN.md)

```bash
pip install mlx-lm
mlx_lm.lora \
  --model Qwen/Qwen3-1.7B-Base \
  --train --data data/finetune \
  --fine-tune-type lora --num-layers 16 \
  --batch-size 4 --iters 1000 --learning-rate 2e-5 \
  --adapter-path adapters/calculearn-v0
# then: mlx_lm.fuse → convert_hf_to_gguf.py → llama.cpp quantize Q4_K_M
```

## Augmentation pipeline (Phase 1b) — v1 dataset (~35k records)

Run on your Mac, in order (needs `npm install` for the Anthropic SDK, plus `pip install datasets`):

```bash
# 1. Synthetic runtime-format data via Claude (same gateway as scripts/authoring/).
#    Resumable; ~4 batches × 10 examples × 4 tasks × 18 concepts (~3k records).
#    Weak areas (ODEs, proof-sketch) get 2x batches per the Phase 2 failure analysis.
npx tsx scripts/finetune/augment.ts            # trial first: --concepts deriv.power-rule --batches 1

# 2. Public data: OpenMathInstruct-2 calculus subset (CC-BY-4.0) + smoltalk
#    general sample (Apache 2.0). MetaMathQA excluded — GPT-synthesized, restrictive.
python scripts/finetune/buildPublicData.py     # ~20k calculus + 6k general

# 3. Mix everything → data/finetune/mixed/{train,valid}.jsonl (dedup, seeded shuffle,
#    native x2 upweight, 15% general cap). Held-out test set untouched.
python scripts/finetune/mixDataset.py

# 4. Train v1 (command printed by the mixer), then score with the same harness:
python scripts/finetune/evalBaseModels.py --models mlx-community/Qwen3-1.7B-bf16 \
  --adapter-path adapters/calculearn-v1
```

Release note: synthetic records are Claude-generated and OpenMathInstruct-2 is
Llama-3.1-generated — review both providers' terms for training-data
redistribution before publishing the dataset.

## Known limitations (v1 — improve in augmentation phase)

- ~1.3k native records is enough for format/behavior adaptation, not for adding
  math ability — augment to 30–50k with filtered public math data + synthetic
  Socratic dialogues via `scripts/authoring/` before the real run.
- Some hint/intro/correct-feedback targets are compositional templates rather
  than fully natural prose; the gold-quality targets are the misconception
  feedback (human-authored `socratic_response_md`) and classifier labels.
- Keep ~15% general instruction data (e.g. smoltalk subset) in the final mix to
  avoid catastrophic forgetting.
